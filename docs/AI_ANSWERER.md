# AI 题库与答题引擎说明

> 本仓库在 OCS 网课助手的基础上，把「固定题库（第三方题库接口）」扩展为「可配置 AI 题库」。
> 填入自己的大模型 API 配置（接口地址 / Key / 模型），脚本就会让 AI 直接作答，
> 不再依赖任何固定题库服务。原有固定题库能力完整保留，可作为兜底。
>
> 安装方法见 [README](../README.md#安装)。本文档说明配置字段、支持的服务、重试机制和常见问题。

---

## 0. 安装与版本标识

从 6.0.0 起，本构建与官方版使用**相同的脚本标识**，安装时脚本管理器会把它当成官方版的新版本，直接替换：

| 元数据 | 官方版 | 本构建 |
| --- | --- | --- |
| `@name` | `OCS 网课助手` | `OCS 网课助手`（相同） |
| `@namespace` | `https://enncy.cn` | `https://enncy.cn`（相同） |
| `@version` | `5.2.3` | `6.0.0`（更高，安装时按升级处理） |
| `@downloadURL` / `@updateURL` | 官方地址 | 本仓库最新 Release 的附件（只会更新到本仓库发布的版本，不会被官方版覆盖回去） |

标准版和通用版标识相同，会互相替换；通用版从 Release 里的通用版文件更新。
旧的「OCS 网课助手 AI 版」（5.2.3-ai.x）命名空间不同，不会被替换，需要在脚本管理器里删除一次。

脚本管理器不允许一个脚本停用另一个脚本。如果页面上仍有另一个 OCS 在运行（旧的 AI 版、另一个脚本管理器里的官方版、
本构建的多个副本），本构建会检测到并**停止答题、不保存也不提交**，同时提示你去停用另一个。
两个脚本同时答题会互相点掉对方选中的多选项并重复提交，所以宁可停下也不并行。
检测方式见 `packages/scripts/src/utils/instance-guard.ts`：其他 OCS 已注册界面组件、页面上存在不属于本实例的悬浮窗、或本构建的另一个副本已登记运行。
另一个 OCS 的悬浮窗被隐藏（Ctrl+O）时无法检测到。

## 1. 快速开始

1. 打开任意网课页面，等待脚本悬浮窗出现；
2. 工具栏点击芯片图标（**AI 题库**）（或在「通用-全局设置 → AI 题库」按钮、「题库配置」旁的 `⋯ → AI 题库` 进入）；
3. 点击右上角 **＋ 添加配置** → 选择供应商预设（如 DeepSeek）；
4. 填入 **API Key**（其余字段已预填）→ 保存；
5. 点击 **测试连接**，看到「连接正常 · xxx ms」即表示可用；
6. 打开「启用 AI 答题」开关（默认关闭）；
7. 进入章节测试 / 作业 / 考试页面，脚本会自动用 AI 作答。

结果面板中，AI 给出的答案会带 **AI** 标签，提示该答案由模型生成、仅供参考。

## 2. 支持哪些服务

协议层面只区分四种，几乎所有主流服务都能覆盖：

| 协议                    | 适用服务                                                                                                                                                             | 请求路径                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `openai`（OpenAI 兼容） | OpenAI、DeepSeek、Moonshot Kimi、智谱 GLM、通义千问（DashScope 兼容模式）、硅基流动、OpenRouter、Groq、Azure OpenAI、Ollama / LM Studio / OneAPI / NewAPI 等自建网关 | `POST {baseUrl}/chat/completions`               |
| `openai-responses`      | OpenAI 官方 Responses 接口、Azure OpenAI（`/openai/v1`）、支持 `/v1/responses` 的中转网关                                                                            | `POST {baseUrl}/responses`                      |
| `anthropic`             | Anthropic Claude 官方                                                                                                                                                | `POST {baseUrl}/messages`                       |
| `gemini`                | Google Gemini 官方                                                                                                                                                   | `POST {baseUrl}/models/{model}:generateContent` |

内置预设见 `packages/core/src/core/ai/presets.ts`；不在列表里的服务选 **自定义（OpenAI 兼容）**，自己填 `baseUrl`（一般以 `/v1` 结尾）。
要用 Responses 接口：先选「OpenAI」或「自定义」预设，再在编辑弹窗里把「协议」改成 **OpenAI Responses（/responses）**，`baseUrl` 不变（如 `https://api.openai.com/v1`）。

Responses 协议的注意事项：

- 推理模型（o 系列、GPT-5、DeepSeek V4 等）的思考过程计入「最大回复 token」，默认 4096；回复被截断时会自动调大后重试；
  也可以在「附加请求体」填 `{"reasoning": {"effort": "low"}}` 减少思考量；
- 推理模型不支持 `temperature` 时会报 400，在「附加请求体」填 `{"temperature": null}` 即可去掉该字段
  （附加请求体里值为 `null` 的字段都会从请求中删除，四种协议通用）；
- 请求带 `store: false`，OpenAI 不会在服务端保存本次答题请求。

## 3. 配置项说明

| 字段                    | 说明                                                                      |
| ----------------------- | ------------------------------------------------------------------------- |
| 名称                    | 仅用于区分多条配置                                                        |
| 协议                    | `openai` / `openai-responses` / `anthropic` / `gemini`                    |
| 接口地址                | 接口根地址，可含版本段；末尾斜杠会自动去掉                                |
| API Key                 | 明文保存在脚本管理器本地存储中                                            |
| 模型                    | 供应商文档中的模型名                                                      |
| 采样温度                | 默认 0（答题需要确定性，同样题目应得到同样答案）                          |
| 最大回复 token          | 默认 4096。思考过程也计入上限；被截断时自动调大重试（见第 8 节）          |
| 超时                    | 单题请求超时，默认 60 秒                                                  |
| 失败重试                | 默认 2 次，**只对 429 / 5xx / 网络错误重试**，401 等配置错误不重试        |
| 图片输入（视觉）        | 开启后会把题目/选项中的图片转 base64 发给模型（模型需支持视觉）           |
| JSON 输出模式           | 要求模型按 JSON 输出（部分推理模型如 `deepseek-reasoner` 不支持，可关闭） |
| Azure api-version       | 仅 `*.openai.azure.com` 需要                                              |
| 附加请求头 / 附加请求体 | JSON 对象，会被合并进请求；用于中转网关的额外鉴权或私有参数               |
| 自定义系统提示词        | 留空使用内置提示词                                                        |

### 全局设置

| 设置项              | 说明                                                               |
| ------------------- | ------------------------------------------------------------------ |
| 启用 AI 答题        | 总开关，默认关闭（避免在用户不知情时把题目发往第三方）             |
| 答题来源            | `仅 AI` / `AI 优先（默认）` / `固定题库优先`                       |
| 并发上限            | 同时向 AI 发起的请求数，默认 2；过高容易触发 429                   |
| 最低置信度          | 低于该值的答案会被丢弃（0 表示全部接受）                           |
| AI 答案写入题库缓存 | 开启后重复题目不再消耗 token；缓存签名包含模型名，换模型后自动失效 |

## 4. 答案是怎么落到页面上的

AI 只负责「题目 → 答案」这一步，产出的答案会被规范化成**与固定题库完全相同的结构**，
再交给既有的匹配器去选中页面上的选项。因此：

- 单选题：模型输出选项字母（如 `B`），匹配器按序号选中对应选项；
- 多选题：输出字母组合（如 `AC`），去重升序后逐个选中；
- 判断题：字母会被**映射成选项原文**（因为判断题匹配器只认「对/正确/错/错误」这类词）；
- 填空题：按空顺序用分隔符连接（默认 `#`），数量必须与页面空数一致，否则该题判失败。

**宁可不答，不可瞎答**：模型输出无法解析、字母越界、填空数量不符时，
该题会标记为失败（结果面板红色序号 + 原因），而不是猜一个选项。
若需要兜底，可在「通用-全局设置 → 高级设置」中开启超星的「随机选择 / 随机填空」。

## 5. 与固定题库的关系

- 固定题库配置、一键获取题库、TikuAdapter 预设、解析器安全扫描**全部保留**；
- 默认「AI 优先」：先问 AI，AI 请求失败或没给出答案时再回退固定题库；
- 关闭 AI 总开关后，行为与改造前**完全一致**（只走固定题库）；
- 两者都未配置时，会统一提示「请配置 AI 题库或题库配置」，不再静默不答题。

## 6. 域名白名单（重要）

脚本用 `GM_xmlhttpRequest` 发请求以绕过跨域限制，但脚本管理器只允许访问 `@connect` 中声明的域名。

- 官方版已预置：`api.openai.com`、`api.anthropic.com`、`generativelanguage.googleapis.com`、
  `api.deepseek.com`、`api.moonshot.cn`、`open.bigmodel.cn`、`api.siliconflow.cn`、`openrouter.ai`、
  `api.groq.com`、`openai.azure.com`、`localhost`、`127.0.0.1`、`aliyuncs.com`；
- **自定义/自建网关**（如自己搭的 OneAPI）不在列表内时：
  - 安装「OCS 全域名通用版」（`ocs.common.user.js`，`@connect *`），或
  - 在脚本管理器中为该脚本手动添加 `@connect 你的域名`；
- 保存配置时脚本会检测域名并提示，避免"明明 Key 是对的却一直失败"。

## 7. 安全与隐私

- **题目内容会发送到你所填的第三方服务**，请自行评估隐私与合规风险；
- API Key 以明文保存在脚本管理器本地存储中（与固定题库配置里含 token 的 URL 同等风险等级），
  请勿在公共电脑上配置；
- Key 在以下位置一律脱敏：面板展示（`sk-abcd…wxyz`）、错误信息、请求日志；
- 由于「请求记录」面板会展示 URL，**Gemini 的 Key 使用请求头传递**，绝不拼进 URL；
- 导出的配置默认把 Key 替换为 `***`，导入后需重新填写。

## 8. 常见问题

| 现象                               | 原因与处理                                                           |
| ---------------------------------- | -------------------------------------------------------------------- |
| 连接失败，提示 401                 | Key 无效或已失效                                                     |
| 连接失败，提示 404                 | `baseUrl` 少了 `/v1`，或模型名写错                                   |
| 连接失败，提示 403                 | 无权限 / 地区限制 / Key 未开通该模型                                 |
| 提示「响应不是合法 JSON」          | 通常是被网关拦截返回了 HTML 错误页，检查地址是否正确                 |
| 提示「AI 答案字母 X 超出选项范围」 | 模型没按格式作答；可换模型、或关闭 JSON 模式后重试                   |
| 题目被判为未搜到                   | 模型无法确定（可调低「最低置信度」或换更强的模型）                   |
| 一直 429                           | 调低「并发上限」，或升级供应商配额                                   |
| 图片题答不出来                     | 该模型不支持视觉；在配置中开启「图片输入（视觉）」并换支持视觉的模型 |
| 提示「模型返回了空内容」/「用完了最大回复 token」 | 见下方「重试机制」，通常会自动恢复；多次出现时调大「最大回复 token」 |

### 重试机制

重试分两层，都不需要手动操作：

1. **请求层**（单次搜题内）：429、5xx、网络错误、超时、空回复、回复被截断都会重试，次数取配置里的「失败重试次数」（默认 2）。
   回复被截断（思考把 token 用完）时，下一次请求把上限调到 4 倍（最多 32768）；
   DeepSeek 系模型第二次仍被截断时，再按 DeepSeek 文档加上 `{"thinking": {"type": "disabled"}}` 关闭思考。
   在「附加请求体」里自己写了 `thinking` 时不会覆盖。
2. **题目层**（答题引擎）：一道题报错、超时、没有答案、答案对不上选项，都会退避后重试（2 秒、4 秒……），
   次数取「通用-全局设置-高级设置-单题尝试次数」（默认 3）。题库正常返回但没收录的题不立即重试。
   全部题目跑完后，再对没答上的题补答若干轮（「收尾补答轮数」，默认 1）。

**提交判断在补答结束后进行**：完成率按最终结果计算，达不到「答案提交方式」设置的比例就只保存不提交。
重试时会跳过本地题库缓存，避免反复用同一个答错的缓存答案。

答题卡中的格子颜色：灰框为未开始，绿色底线在动为搜题中，琥珀色为等待重试，红色为重试后仍没答上，绿色实心为已作答。

### 跳转后第一题答不上

原因是超星的题目文字用加密字体显示，脚本要先解密再读题。章节测试里解密和答题由两个脚本实例分别进行，
旧版本答题时没有等解密完成，第一题经常读到密文。现在读题前会等待解密结束（最长 30 秒），
逐题作答的作业/考试在点下一题后也会等新题目渲染出来再读题，而不是固定等 1 秒。

## 9. 开发者信息

### 代码结构

```
packages/core/src/core/ai/        # 纯逻辑（无 DOM 依赖，可在 Node 下单测）
  interface.ts                    # 类型契约、AiError
  presets.ts                      # 供应商预设
  prompt.ts                       # 提示词组装（纯函数）
  providers.ts                    # 各协议：请求组装 / 响应解析
  parser.ts                       # 模型输出解析与答案规范化
  transport.ts                    # 发送、超时、重试、错误归类、脱敏
  answerer.ts                     # → SearchInformation[]

packages/scripts/src/utils/ai/    # 与脚本运行环境相关的部分
  config.ts                       # 配置归一化 / 读取 / 校验 / 脱敏
  answerer.ts                     # AI 与固定题库的合并调度、并发与去重
  ui.ts                           # 配置面板

packages/scripts/src/utils/hash.ts  # 题目缓存签名
```

### 测试

```bash
npx tsx tests/ai-answerer.test.ts   # 或 npm run test:ai
npm run test:engine                 # 答题引擎：重试、补答、提交判断、页面就绪、暂停/关闭、多实例停用
```

覆盖：提示词组装、输出解析、答案规范化（含越界/数量不符拒绝）、
「AI 答案 → 既有匹配器」端到端回归、各协议的请求组装与响应解析、传输层重试与错误码、脱敏。

### 扩展新协议

在 `providers.ts` 中新增 `buildXxxRequest` / `parseXxxResponse` 分支，并在
`interface.ts` 的 `AiProtocol` 中登记即可；UI 的协议下拉在 `utils/ai/ui.ts`。
